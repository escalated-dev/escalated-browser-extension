# Escalated browser extension v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Chrome MV3 side panel extension that lets an agent connect to their helpdesk by signing in, work their queue, read and answer tickets, triage, get badge counts and alerts, and create tickets from the page, against any backend serving staff API contract v1 (first: Laravel 1.9.21).

**Architecture:** One service worker owns all network calls, polling, the badge, notifications and the context menu; the side panel (Vue 3) talks to it with typed `chrome.runtime` messages. A small typed API client (types generated from the contract's OpenAPI file) is shared by both. State lives in `chrome.storage.local` (trusted contexts only); nothing lives only in memory.

**Tech Stack:** TypeScript 5, Vue 3.5, Vite 7, Tailwind 4, Vitest 4 (+ `@vue/test-utils`, `happy-dom`), Playwright (Chromium with the unpacked extension), `openapi-typescript` 7, ESLint + Prettier (pinned), Node 22/24.

**Spec:** `docs/superpowers/specs/2026-11-26-escalated-browser-extension-design.md`. Contract: `escalated-developer-context/contracts/staff-api-v1.openapi.yaml` (plan 1). Backend: plan 2.

**Repo:** `escalated-dev/escalated-browser-extension` (local `C:\Users\work\escalated-browser-extension`), work on branch `feat/v1`.

## Global Constraints

- Manifest V3; `minimum_chrome_version` `"116"` (side panel `open()` from user gesture). Permissions exactly: `sidePanel`, `storage`, `alarms`, `notifications`, `contextMenus`, `identity`. `optional_host_permissions`: `["https://*/*", "http://*/*"]`. No `host_permissions`, no content scripts, no `scripting`, no remote code, no `eval`/`new Function`, CSP default.
- All API calls from the service worker or extension pages; never from content scripts (there are none).
- Token stored only in `chrome.storage.local` after `chrome.storage.local.setAccessLevel({accessLevel: 'TRUSTED_CONTEXTS'})`; never logged, never in `storage.sync`, never in a URL.
- Polling: `chrome.alarms` named `poll` every 1 minute, recreated on `runtime.onStartup` and `onInstalled`. On 429 honour `Retry-After`; on network errors back off 1, 2, 5, 10 minutes, reset on success; on 401 stop polling, clear the token, badge `!` and show "Reconnect" in the panel.
- One connected helpdesk at a time. Disconnect calls `POST /auth/revoke` (best effort), then clears storage and calls `chrome.permissions.remove` for that origin.
- Discovery order for `{address}`: `/support/api/v1/meta`, `/wp-json/escalated/v1/meta`, `/escalated/api/v1/meta`, `/escalated/api/meta`; Advanced "API path" overrides it. Connect page for sign-in: `/meta.connect_url`; when it is null, only the manual token path is offered. Ticket links: `/meta.web_url_template`.
- Features missing from `/meta.features` are hidden, never shown broken.
- UI copy: plain, short, no em dashes; English only in v1 with all strings in `src/i18n/en.ts` so locales can follow.
- Look: dense, matches the agent panel tokens of `@escalated-dev/escalated` (copy the CSS custom properties, do not depend on the package). Light and dark follow `prefers-color-scheme`.
- No analytics, no third-party requests. Patch version bumps after 1.0.0 (start at `0.1.0` until store submission, then `1.0.0`).
- No "Claude", "Filament" or AI mentions in commits or PRs. README short; detail in `docs/`.

## Review Focus

- Service worker killed mid-poll or between alarm and fetch: the next alarm must pick up from `lastPollAt` in storage, never notify twice for the same ticket event (dedupe key `reference + updated_at + kind` kept for 24 h).
- Helpdesk on plain `http://` (local installs): connect works (Chrome allows `launchWebAuthFlow` to an http page), and the panel shows a one-line "not encrypted" warning.
- Address typed with a trailing slash, a path (`https://example.com/support`), uppercase, or no scheme: normalised to the origin plus base path; no scheme defaults to `https://`.
- Reply box content survives switching tickets or closing the panel (draft per ticket in `storage.session`).
- Very long threads (500 replies) and ticket bodies with HTML: bodies render as text with line breaks (no `v-html`), list stays scrollable and the newest reply is visible on open.
